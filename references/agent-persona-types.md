# Agent 人格类型说明

## 三种人格类型

### 1. 功能型 (functional)

**定位**: 一次性任务执行器

**特征**:
- 短生命周期（一次性任务）
- 明确的输入输出契约
- 由 main 编排调度
- 不直接面向用户

**文件配置**:
```
functional-agent/
├── SOUL.md          # 简化版：执行风格
└── AGENTS.md        # 任务契约：输入输出、职责边界
```

**记忆系统**: 无

**示例**:
- 临时 coding agent
- 单次数据处理任务
- 中间步骤执行器

---

### 2. 职能型 (operational)

**定位**: 长期协作角色

**特征**:
- 长期存在（持续运行）
- 有稳定的职责边界
- 需要积累经验
- 可能直接面向特定场景

**文件配置**:
```
operational-agent/
├── IDENTITY.md      # 轻量版：名字 + 角色 + emoji
├── SOUL.md          # 标准版：判断原则 + 边界
├── AGENTS.md        # 完整版：职责 + 执行规则 + 服务对象段
└── memory/          # 可选：日志目录
    └── YYYY-MM-DD.md
```

**可选增长**:
- `MEMORY.md` — 踩坑记录
- `TOOLS.md` — 工具链坑位
- `HEARTBEAT.md` — 巡检规则

**记忆系统**: 文件系统 (memory/*.md)

**示例**:
- monitor（监控哨）
- control-plane（守夜人）
- wemedia（自媒体管家）

---

### 3. 独立人格型 (independent)

**定位**: 完整人格实体

**特征**:
- 直接面向用户
- 需要建立信任关系
- 有独立的价值观和判断体系
- 需要长期记忆和学习

**文件配置**:
```
independent-agent/
├── IDENTITY.md      # 完整版：名字 + 角色 + 气质 + emoji + 灵感
├── SOUL.md          # 完整版：核心身份 + 原则 + 边界 + 风格
├── USER.md          # 独立文件：服务对象背景 + 硬规则 + 偏好
├── AGENTS.md        # 完整版：职责 + 执行规则 + 通知规则 + 记忆规则
├── HEARTBEAT.md     # 完整版：健康检查 + 巡检规则
├── TOOLS.md         # 完整版：工具链坑位
├── MEMORY.md        # 完整版：长期伤疤 + 稳定规则
└── memory/          # 完整：日志 + 归档
    ├── YYYY-MM-DD.md
    └── topics/*.md
```

**记忆系统**: 独立 memory-lancedb-pro + 文件系统

**示例**:
- main（晨星）
- 面向不同用户的独立 agent

---

## 判断标准

| 维度 | 功能型 | 职能型 | 独立人格型 |
|------|--------|--------|------------|
| **生命周期** | 一次性 | 长期存在 | 长期存在 |
| **面向对象** | 其他 agent | 特定场景 | 直接面向用户 |
| **信任关系** | 无需建立 | 职能信任 | 需要建立 |
| **经验积累** | 不需要 | 需要 | 需要 |
| **记忆系统** | 无 | 文件系统 | 独立向量检索 |
| **人格复杂度** | 无 | 轻量 | 完整 |

## 使用建议

### 何时选择功能型
- 临时任务，用完即弃
- 不需要积累经验
- 由其他 agent 调用

### 何时选择职能型
- 长期运行的功能模块
- 需要积累经验但不直接面向用户
- 有明确的职责边界

### 何时选择独立人格型
- 直接面向用户的主 agent
- 需要建立长期信任关系
- 需要跨会话记忆和学习
